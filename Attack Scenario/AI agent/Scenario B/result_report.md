## 📜 1. 개요 (Executive Summary)

본 테스트는 웹 애플리케이션 보안 취약점을 체계적으로 검증하기 위해 설계되었습니다. 공격은 **접근 권한 확보 → 원격 실행 환경 구축(Reverse Shell) → 내부 시스템 정보 수집 및 기밀 데이터 탈취**의 단계로 진행되었으며, 매우 높은 수준의 성공률을 보였습니다.

*   **최종 결론:** 대상 웹 애플리케이션은 명령어 주입(Command Injection), 인증 관리 부실 등 다수의 심각한 보안 취약점을 포함하고 있으며, 공격자가 내부 시스템에 접근하여 **주요 서비스의 API 키 및 토큰**을 탈취하는 데 성공했습니다.
*   **권고 사항:** 모든 사용자 입력값 검증 철저화, 최소 권한 원칙 적용, 그리고 비밀 정보(Secret) 관리를 위한 전용 Vault 솔루션 도입이 시급합니다.

## 🔍 2. 세부 분석 및 발견된 취약점 (Detailed Findings)

### 2.1. 인증 및 접근 제어 우회 (Authentication & Access Control Bypass)
*   **세션 관리:** `bwapp_cookie.txt`를 통해 확보한 쿠키 (`PHPSESSID=n4snjb2dd7j98hcdr9ea4ntj17`)는 해당 시스템에 대한 유효 세션을 가졌음을 의미하며, 이를 기반으로 추가적인 테스트가 진행되었습니다.
*   **취약점:** 로그인 과정에서 사용되는 `security_level` 파라미터 조작(예: `&security_level=0`)을 통해 제한된 기능 영역에 접근할 수 있음을 확인했습니다.

### 📡 2.2. 원격 명령어 실행 환경 확보 (Reverse Shell Establishment)
*   **성공 내용:** 웹 애플리케이션의 취약점을 악용하여 성공적으로 리버스 셸(Reverse Shell)을 구축하는 데 성공했습니다. 이는 공격자가 목표 시스템 내에서 운영체제 수준의 명령어를 실행할 수 있는 권한(Command Execution Capability)이 확보되었음을 의미합니다.
*   **실행 명령어 예시:** `ls -la /tmp/*.php`, `cat+/etc/passwd`, `ifconfig` 등 내부 파일 및 네트워크 정보를 조회하는 명령어가 성공적으로 수행되었습니다.

### 🌐 2.3. 시스템 환경 탐색 (Internal System Enumeration)
테스트 로그 전문(`reverse_shell_test.log`)을 분석한 결과, 공격자는 다음과 같은 내부 인프라의 존재를 확인했습니다:
*   **Docker 컨테이너 구조:** Docker API 호출을 통해 현재 실행 중인 서비스 목록과 이미지 ID(예: `sme_attack_lab-admin_entry`, `client_c_bwapp`)가 성공적으로 나열되었습니다. 이는 시스템이 다수의 마이크로서비스로 구성되어 있음을 나타냅니다.
*   **핵심 인프라 식별:** `mysql:5.7` 버전의 데이터베이스 컨테이너 및 `hashicorp/vault:latest`와 같은 보안 솔루션 관련 서비스가 운영 중임을 확인했습니다.

### 🔐 2.4. 핵심 기밀 정보 탈취 (Critical Data Exfiltration - **CRITICAL FINDING**)
시나리오의 가장 심각한 발견 사항입니다. 공격자는 취약점을 이용해 Vault 컨테이너에 접근하고, `scan_token.php`를 실행하여 내부 시스템 관리 및 서비스 운영에 필수적인 비밀 키들을 성공적으로 탈취했습니다.
